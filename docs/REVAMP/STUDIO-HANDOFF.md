# Studio handoff — signature checkpoint

Cloud source/build work needs no Local-mode switch and no running owner laptop. A supported Windows/macOS Studio host (including an authorized remote host) is needed for actual imports and engine tests. Studio was not available/used in this cloud session.

1. Download the draft PR's latest CI artifact, or clone the branch and run `bash scripts/check.sh`. Open `build/Ascension-Signature.rbxl` in Studio. This is the new signature diagnostic build. `build/Riftwake.rbxl` is the legacy adapter. Verify artifact SHA against `build/SHA256SUMS`.
2. For live source sync, install the compatible Rojo Studio plugin and use `.tools/rojo serve ascension.project.json`, then Connect/Sync. Rojo sync is optional when opening the built file. Commit changes made in Studio back as source/assets; do not let Studio become the sole copy.
3. Select R15, start solo Play. The HUD must explicitly report Studio source preview and47 pending assets. The neutral transparent collision proxy intentionally differs from the source hero render. No production assets should be silently substituted. Studio DataStores are off by default; use disposable fixtures before any private service testing.
4. Enter Warden. Mouse1 tap light/hold≥.25s heavy, T direct heavy, F guard/parry, Q dash, E Coreburst (earned Lv2), R Overdrive (earned Lv5), Shift sprint; controller R2/R1/L2/B/X/Y/L3; touch buttons. Movement/jump use native controls. Skill unlocks follow existing progression; use a separate local fixture to inspect higher-level abilities, not production balance edits.
5. Import FBX via Studio's 3D importer: inspect scale/up-axis, named R15 bones, skin weights, model segmentation and collision. Preserve normalized dimensions and server-created Humanoid/Animator. Do not assume matching names alone make an FBX a valid playable R15 character. Validate first, then replace diagnostic templates with imported rigs and blade attachments. Keep source/world transforms in the registry.
6. Import animations using the official supported Animation Editor workflow. Inspect each named take; if bulk-FBX takes do not separate cleanly, export individual actions from the committed `.blend`. Confirm HitStart/HitEnd/TrailOn/TrailOff/FootLeft/FootRight/impact markers against the catalogue. Publish only under the permitted experience owner/group and record actual IDs, ownership and hash/evidence. Audio imports likewise require authorized owned IDs. Do not pay for resources; asset publishing authorization is distinct from this source checkpoint.
7. Update manifest ownership/IDs/status only after actual import/validation; regenerate ModuleScript via manifest.py and format with `.tools/stylua src` before checks. Source KeyframeSequence registration works only for diagnostics and is not production ownership. Runtime remains Studio-only even if IDs are populated until the gate is deliberately completed in source.
8. Start a local server with4 clients. Create party, invite other clients, accept, Ready each, leader Enter. Also test simultaneous solo encounters and outsider targeting. Run the latency/security/cleanup cases in13-PERFORMANCE-AND-TESTING and retain captures/logs tied to exact SHA.
9. Record defects rather than declaring success. Supply actual engine captures and joint/marker/collision/navigation evidence before gate B is closed. Physical device/performance studies and publication remain separate later gates.
