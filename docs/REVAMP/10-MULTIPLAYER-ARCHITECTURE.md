# Multiplayer architecture

Shared sanctuary → party creation/invite/accept → per-member Ready → leader enters → frozen encounter roster → contributions/results → return. Solo skips party creation. Server-side maximum is four clients for the signature checkpoint. Eight arena slots are pooled by slot ownership; actual templates clone when allocated and destroy when released. Eight-player support is unvalidated and not enabled.

PartyState owns leader, members, expiring invitations, readiness and encounter lock. EncounterState owns unique roster1–4, membership, fixed size/health scale, departures and60s reconnect. EncounterService maps UserId to active encounter, keeps NPC/arena together, limits targeting to members and rejects outsider damage. Nonparticipants cannot grant rewards. Player/NPC collision groups disable actor-to-actor physical pushing; obstruction casts use the same groups so outsiders cannot act as physical/raycast shields. Actual engine collision isolation is still unverified. Health scaling is1+.55×(initialSize−1); departures never reduce it. Rewards require positive damage/parry contribution and the unchanged existing progression grant.

State replication is targeted per player; combat events go only to the roster. Encounter IDs are prefixed with a per-server GUID before the bounded reward ledger. Server-created NPC Humanoids/Animators use server ownership. Navigation token bucket limits new path requests globally to4/sec and per actor to1/sec, with asynchronous generation guards, failed-path stop and10s stuck reset. Verify pathing and rotation in Studio; structural tests cannot prove them.

Current limitations: disconnect removes party membership but keeps encounter eligibility60s; rejoin restores encounter position, not the former party invitation/readiness state. Death respawns in sanctuary; Enter rejoins a still-active attempt with its existing difficulty, not automatically. Results are diagnostic notices rather than a finished results/inventory screen. Cross-server reconnect is unsupported. Document these defects before claiming complete recovery.

Engine tests must try malformed/replayed/distant/dead/wrong-encounter requests, late joins, all-ready races, disconnect during charge/reward, server shutdown, pool exhaustion and simultaneous solo encounters at1/2/4/8 workloads. Client-visible outcomes and server logs must show isolation under0/100/200ms simulated latency.
