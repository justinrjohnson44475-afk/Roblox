# Studio handoff and setup

## Artifact preview (no cloud connection required)
Build in Cloud or download a successful GitHub build. Open the binary/XML place in supported Studio, then Play. Only the floor/spawn are static; all harbor models and UI are generated by scripts at runtime. In Explorer inspect ReplicatedStorage.Shared, ServerScriptService.Server and StarterPlayer.StarterPlayerScripts.Client. Output must have no errors. Record the Git commit and artifact SHA256 with each test result.

Expected first action: approach any teal crate, hold its ProximityPrompt, see supplies increase, then approach “Mend the pier.” Deposit supplies; carried amount decreases and tokens increase by two per deposited unit. After eight contributions the pier becomes solid and the greenhouse station becomes active. Twelve units restore the greenhouse; sixteen relight the beacon. After the celebration a new shift starts. Opening the workshop should allow the free amber color and earned colors. Native keyboard, touch and controller prompts need separate testing.

## Test universe and persistence
1. Create a separate private Roblox experience through Studio/Creator Dashboard; confirm account/group ownership. Do not use production data for development.
2. Save/publish only the private test experience after the owner authorizes that account action. Cloud has not done so.
3. For Studio DataStore integration tests, enable **Game Settings → Security → Enable Studio Access to API Services** for the test experience and set `EnableStudioDataStore` true in a test configuration. Keep this configuration out of production source defaults.
4. Earn tokens, wait for autosave or leave, rejoin and compare inventory. Exercise two-server access, connection failure, final save failure, rapid rejoin and expired lease recovery. Mock tests are not substitutes.
5. Restore the memory-only Studio default after testing. Check DataStore version history and document backup/recovery instructions before beta.

## Purchase and analytics tests
Create a cosmetic-only game pass under the test experience. Verify benefits, advertised value, permissions, actual regional pricing and ownership queries. A real purchase may charge Robux; use current Roblox test tooling and authorized test accounts. No test purchases have been made. There are no developer products, receipt callbacks or consumable rewards in this slice. If added later, receipts must be durable and idempotent before sale.

Custom events are disabled; enable only for a published private test and check the actual Creator Dashboard. FirstContribution is first-ever donation on the profile, not per-session onboarding. RepairCompleted counts participating players for each completed repair. Reading triggers no event. Core retention and acquisition metrics should come from Roblox dashboards.

## Editing with Rojo
Use a local checkout of the exact Git commit, `aftman install`, a matching Rojo Studio plugin, and `rojo serve default.project.json`. Connect to localhost:34872. Runtime instance changes disappear on Stop and are not source edits. Change World.luau/config/UI or deliberately export a reviewed asset into source, then rebuild. Do not rely on uncommitted Studio-only changes. Preserve attribution and moderation IDs for future assets.

No requirement to change Codex chat mode. A future authorized Windows/macOS remote Studio host could perform these steps without the owner’s laptop; that host is not configured here.
